# Maintainer specification review — Slice A

Open a durable job, choose **Reviewable fields**, enter a local reviewer label, and select a specification. The connected workspace presents its manufacturer evidence beside one interpretation editor when container space permits. Search properties in ordinary language, compare their meaning/direction/units, select an explicitly eligible property, inspect the server conversion preview, explain the decision, and **Save and next outstanding item**. **Save decision** stays on the item; **Return to saved review** reloads durable decisions after explicit discard of unsaved input.

Saving records non-authoritative progress. The reviewer label is unauthenticated. Saving does not approve, publish, engineering-verify, recapture or prepare a component. Required decisions being recorded does not mean every engineering meaning is resolved. Product field approval controls retain their separate ownership in **Product field approval and advanced proposal details**.

## Original Slice A and stabilization ownership

Original Slice A introduced the 34-property presentation catalog, source-context DTO/panel, stable selected editor, snapshot/intent guards, saved-queue advancement and full-route regression tests. This stabilization keeps those contracts and adds a searchable compact queue, lazy advanced cards, shared contextual help, recursive evidence layout fixes, container-responsive workspace design, and a 15-scenario isolated lab. No canonical schema, interpretation contract, source evidence, acquisition, PDF extraction or verification authority was changed.

`ReviewerProperties.tsx` owns presentation labels/descriptions/search vocabulary only. Returned server descriptors own eligibility, dimensions, units and normalization. Catalog coverage compares all existing direct descriptors; no target is guessed, auto-selected or synthesized. Missing search results do not establish a missing engineering property. That decision records a topic/explanation and creates no field. Compare-result details and shared help explain similar meanings without flooding the main flow.

Selection/save/navigation remain owned by `SemanticAdjudication`. One editor is keyed by proposal ID outside changing work groups, so moving from required to reviewed or refreshing a snapshot does not remount its input. Unsaved navigation requires explicit discard; busy operations block transitions. Failed saves retain input and never retry automatically. Changed snapshots invalidate preview; failed reload requires another explicit reload, and successful reload still requires evidence confirmation. Successful returned durable state alone owns next-item selection and completion wording. Advanced card controls retain the original first-contributor ownership of field/fact/qualified approval; closing diagnostics unmounts their presentation, while selections remain in the ProductReview parent.

## Layout and help rationale

The screenshot's vertical text came from global two-column `dl` grids applied recursively to ReviewValue objects whose children were wrapper divs. Each nested grid allocated columns to those wrappers, then narrowed its own nested labels/values; `overflow-wrap: anywhere` permitted near-zero-width text. Viewport-only stacking could not account for narrower nested containers.

ReviewValue objects now use full-width `dt`/`dd` entries, with block layout independent of the parent grid. Exact unbroken technical text uses focusable local horizontal scrollers; its value is unchanged. Ordinary prose wraps at words. Container queries determine workspace columns from usable width rather than viewport size: 68rem supports the queue/sidebar layout, 48rem supports evidence/editor columns, and 30rem supports label/value rows in the evidence panel. These are adjustable readability choices, not engineering limits. Unsupported container queries retain the stacked fallback. The queue's 15rem visual scroll budget does not truncate facts; all items remain searchable/reachable. Hundreds of diagnostic cards mount only when explicitly expanded. Empty detailed groups exist only inside that advanced area.

`ReviewHelp` is a single inline help pattern: Tab focus leaves it closed; click/tap or Enter/Space toggles it; Escape/Close dismisses it; focus returns to the trigger after panel dismissal, and leaving closes it. ARIA expanded/controls/description connect the help to its trigger. Inline content avoids off-screen floating popovers in narrow containers. Essential unknown-context, qualifier and authority warnings remain directly visible. Missing duration/temperature/revision are compactly displayed as unknown; missing other conditions does not contradict explicitly retained duration/temperature. Exact applicability identifiers and technical locators remain expandable.

## Final source-first workflow correction (2026-10-10)

The normal workspace reads queue → manufacturer evidence → engineering interpretation, in both DOM and visual order. The compact product header owns the local reviewer label; readiness links return focus to it. Product approval/rejection/deferral and engineering verification retain their separate contracts and controls.

Source binding is deliberately separate from engineering assignment. A single exact, non-conflicting bound statement has a read-only supporting summary. Uncertain or competing observations require an explicit choice beside source wording. An existing durable decision retains its exact selected IDs; stale IDs remain visible as a blocked binding rather than silently replacing them. Changing evidence clears target, unit clarification and preview before a new discovery request. Source scope and material conditions remain prominent, including requested-versus-source model mismatches. Normalization may succeed while projection is unavailable; the UI never converts that success into applicability or approval.

Current interpretation distinguishes no assignment, provisional automatic suggestion and durable human disposition/revision. Corrections append decisions. Queue search spans all current-job review groups, labels, original values/wording and readable review status; filtered groups open, matching counts remain visible, and search never changes the selected editor or drafts.

`reviewer-properties.v1` retains the existing 34 direct-review descriptions. `component-explorer.v1` additionally indexes explicitly selected engineering sections of `component.schema.json` and its `canonicalQualifiedValue` target enumeration. The presentation index grants no canonical target, alias rule, normalization, or eligibility permission. Schema structures with open-ended contents are browsable as structures; arbitrary leaf names are not invented. Undocumented descriptions remain marked as such. Property-name unit hints describe naming conventions only; server descriptors own actual units/dimensions. Topology/interface/protection details outside the bounded index, other platform registries and proposed concepts are not presented as a complete vocabulary.

Inline results and the modal explorer use that same index and latest server response. Results show eligible properties first and explain known unavailable concepts. Text search misses, valid empty discovery, loading, failure, stale snapshot and absent evidence are distinct. Twelve compact inline results and their 22rem scroll height are presentation reading budgets, not semantic limits: every indexed result remains in the explorer. Choosing a property compacts results to emphasize preview/rationale/readiness; typing or Change selected property restores them. The native modal owns focus/inert behavior, Escape closes it, and closing restores focus without scrolling or clearing the form. Narrow screens use a full-width modal.

Readiness follows the existing semantic decision contract: all dispositions require local reviewer identity, current source binding and snapshot. Map requires an eligible target, successful current server preview and rationale. Possible missing property additionally requires topic and explanation. Reject interpretation and Not applicable require rationale; unresolved/evidence-only notes remain optional. Missing requirements focus the corresponding input. Failed or stale responses retain drafts and require explicit recheck; no save replay occurs. Save-and-next advances only from successful returned durable state.

The provenance view now allowlists capture identity independently of fact presentation metadata. Production qualified facts require metadata; the missing-metadata test is deliberately defensive presentation input, not acceptance of an invalid domain artifact. No captured bodies, local paths or new file reads enter the DTO.
