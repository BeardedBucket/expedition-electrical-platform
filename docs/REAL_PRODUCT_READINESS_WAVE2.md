# Wave 2: genuine evidence in durable review

This document describes the earlier automatic/native preparation slice. The
cumulative direct-document authoring, additional genuine sources, conditional
v2 corrections and draft consumers are documented in
[WAVE2_DIRECT_PRODUCT_AUTHORING.md](WAVE2_DIRECT_PRODUCT_AUTHORING.md).

This implementation prepares eight existing investigation IDs without admitting a
product. The 47-ID horizon is unchanged. Real job and byte stores remain private;
public data contains assertion names, citations, digests and honest holds. Ordinary
`review_ready` means that an operator queue exists, not that an intended-use
inventory is complete. A read-only correction preview is not a human source event.

## Reproducible preparation and source correction

Build the workspaces, then use `scripts/prepare-wave2-review.mjs` with explicit
retained receipts, IDs and a fresh external `engineering-corpus-wave2-private`
root. The tool uses `IngestionJobService`, `FileIngestionJobStore` and
`LocalSnapshotStore`; there is no disposable candidate bridge in place of the
durable workflow. It reloads every prepared job. An optional single explicit
supplemental source root lets BMV's technical HTML supplement its original PDF
without overwriting old bytes. Missing/mismatched receipts or bytes fail.

Newpowa's published SKU is independently present in its source Product and native
Product Code row. Supplying that MPN fixes the previous model-only intake hold;
an intake alias cannot substitute for this proof. `MPPT 150/45` is the literal
manual table header. It does not establish a SmartSolar retail ordering code,
hardware revision, tracker count or terminal identity. The existing reviewed
Victron acquisition profile supplies its existing publisher/domain mechanics;
this change neither authors nor upgrades a reviewed acquisition profile.

`source-product-html` 3.0.0 and `native-model-review` 1.0.0 emit private
`source-owned-specification.v1` records. Each retains native label, value, model,
separate locators, and the complete containing region. The readable statement is
an explicitly reconstructed label/value pair, not a newly quoted manufacturer
sentence. HTML spans prove column membership without expanding cells or
transferring a sibling's independent value. Nested, ragged, repeated or ambiguous
axes fail as a whole. PDF layout and existing PDF qualifiers are unchanged.

The new producer intentionally uses the existing HTML input, item and per-block
UTF-16 text bounds. Blocks plus facts count as two items per observation; encoded
JSON length also counts toward the text cap. A record exceeding a bound is
rejected whole, never cropped. Complete ordinary extraction is required. These
are independently applied supplemental output envelopes, not larger transport
allowances or a claim that combined job storage is bounded by one parser cap.
Full source context is intentionally repeated in records and detached human
proofs; review/storage cost remains a measured follow-up, not concealed deduplication.

In the existing source editor, **Proposed engineering source facts → Use source
suggestion for a correction** loads the complete citation and suggested meaning.
It saves nothing. A single existing automatic observation at the same source
position is corrected; a genuinely missing observation is added. Competing
observations withhold the shortcut. Existing human corrections are not repeatedly
suggested. The reviewer can inspect source context, change the interpretation,
preview, enter a rationale and deliberately save. Edits invalidate preview;
durable CAS, original-document equality and append-only source/semantic history
remain authoritative. Cropped encoded records, foreign model ownership, forged
citations and unconditional scalar projection fail. The source navigator still
supports entirely missed facts and unsupported sources through manual correction
or explicit unresolved drafts.

`scripts/preview-wave2-review.mjs` performs only read-only genuine previews,
restarts and exact snapshot byte replay. It verifies that no durable human event
was written. Its prospective candidate has preview-event identifiers and **must
not be counted as human-adjudicated**. A future deliberate human save creates its
own durable event and reconstructs the atomic candidate. Product approval,
canonical promotion and content-bound engineering verification remain separate.

## Typed consumers and replay

`engineering-profile.v1` gains optional independently versioned
`battery-operating.v1` and `instrumentation.v1` contracts. Original profiles and
archived envelope v1 replay are unchanged. Existing eight scalar PV quantities
still use `engineering-profile-adjudication.v1`; conditional quantities use v2
and retain their specific quantity, source unit and source decision identity.
The generator synchronizes the portable and inline canonical profile schemas.
Human mapping schema, DTO discovery and UI choices include the same quantities.
Unknown profile/subcontract, source-record and scenario versions fail closed.

Battery source ranges retain Celsius and published Fahrenheit wording in source
proof. The supported dual-unit grammar requires exact endpoint equivalence;
9/5 and 32 are the defined Celsius/Fahrenheit affine conversion, not tolerances.
No tolerance is invented for inconsistent manufacturer renderings. Typed values
use degC while original native strings remain authoritative. A cell-charge range
cannot be compared to ambient temperature. A discharge range whose measurement
location is unspecified remains `unknown`. `after_heating` is a source condition,
not an inferred heater capability or permission to charge a cold cell.

Series/parallel counts are explicit permissions, with separately retained bank
matching requirements. Missing permission/conditions remain unknown. Allowed
count comparisons do not prove physical bank membership; that stays an explicit
mandatory hold even when a caller declares matching. Allowed
operating ranges never become BMS cutoffs, recovery thresholds or derating curves.
Optional cutoff data can be retained, but this slice deliberately does not execute
BMS transitions, recovery, interpolation or current/duration/thermal dynamics.

Instrumentation separates measured quantity and independently supported electrical
domain, percentage error, denominator, optional range/temperature and nominal
shunt A/mV transfer. Neither DC supply nor a battery label proves measurement
domain. A bare published accuracy
percentage retains `basis: unknown`; resolution is never accuracy. A nominal
shunt transfer point does not establish a maximum measurable current. That
separate optional limit needs independent quantity/domain evidence before a
comparison. Shunt values do not become device consumption, battery capability,
protective capacity or a thermal/interruption rating. Alternative nominal
transfer requires separate calibration evidence; included accessories do not
establish a mandatory-only installation. A supplied calibration
reference is not a modeled calibration proof.

The Node Phase 3 entry exports `bindInstalledOperating`,
`evaluateInstalledOperating` and `replayInstalledOperating`.
`bindProductSelection(..., {installed_operating})` applies the same gate after
preserving architecture/selection/PV conditions. It adds no ports, wires, roles
or commercial inputs. Each use names an existing exact component instance.
Checks retain quantity evidence IDs; explicit cell-temperature rationale and
scenario assumptions are bound in the portable wrapper. Inclusive source
boundaries use finite unrounded comparisons without a default margin.
Known contradiction yields BLOCKED even with missing BMS, calibration or authority.
Otherwise missing required evidence yields UNRESOLVED. Positive subchecks are
only bounded predicate results. The inherited gate cannot grant installation or
verified-product eligibility. Replay reconstructs exact source/record/scenario
snapshots and rejects changed results even after rehashing. Inputs/results are
owned copies. Existing independent canonical verification still binds all content.

The earlier captures left PV reference conditions held. Direct review of the
subsequently captured exact Newpowa datasheets establishes their published STC
reference and separate Voc/Isc/power coefficients as unreviewed proposals.
Coefficient domains, beta-Vmp, operating upper-voltage basis, tracker/terminal
identity and connection/protection proof still remain held. No wire or generic
installation permission is invented. Multimode AC/grounding/current sharing
retain existing contracts plus directly authored mode/condition facts; stateful
and physical installation gaps are explicit in the cumulative coverage report.

## Genuine acceptance and measurement

`scripts/run-wave2-genuine-demo.mjs` requires actual private jobs, exact retained
bytes and clearly labeled undecided meaning previews. It fails when prerequisites
are absent. It runs actual Phase 3 and Phase 5 consumers for explicit 12/24/48 V
design intents. Missing real ports/path witnesses prevent exact materialization;
no invented interfaces force a positive selection. The PV example retains unknown
electrical calculations and proves physical-count NO precedence. The battery/
monitor example executes genuine source temperature/count predicates and retains
the published nominal shunt point, while its measurement limit stays unknown. It
retains unknown accuracy denominator, calibration, BMS and authority.
Full wrappers stay private because they embed source context; small metadata
results are reviewable without publishing third-party page text.

The unchanged pinned three-document frozen observation evaluation and original
source-sibling sample yield zero new usable assertions. No extractor investment
continues after that result. Historical 341/254 and 77 denominators are neither
relabelled nor remeasured in full. New native qualification, ordinary projected
proposals, read-only typed previews and human source decisions are reported
separately. Human correction time and real operator acceptance remain unmeasured.
Normal tests use explicitly invented project-authored sources, without TEMP
dependencies. Genuine observation/demo gates require explicit private inputs and
fail rather than silently skip missing evidence.

STOP for human actual-code review and operator validation. No workflow command
here stages, commits, pushes, promotes, verifies or approves a real product.
